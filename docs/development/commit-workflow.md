# 提交工作流

本仓库把“验证通过”和“提交代码”视为同一个开发闭环。代码变更必须按以下顺序完成：

1. 修改代码、测试和必要文档。
2. 构建受影响模块，运行受影响测试，并完成必要的真实运行验证。
3. 检查 `git diff --check`、Markdown 链接和最终差异。
4. 只有在所有必要验证通过后，执行一次 `git commit`。
5. 交付说明中报告测试结果和提交哈希。

提交规则：

- 只暂存本次任务改动；已有工作区改动、构建目录、日志和临时文件不得混入。
- 测试失败或验证未完成时，不得以完成状态提交代码。
- 无法准确区分改动归属时，不得擅自提交，应先报告。
- 文档-only 变更至少通过 Markdown 链接检查和 `git diff --check` 后再提交。
- 该规则要求创建本地 Git 提交，不自动推送远程仓库。
