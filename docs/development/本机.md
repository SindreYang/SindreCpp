## vcpkg 使用方式

vcpkg 不在当前会话的 `PATH` 中。需要使用 vcpkg 时，直接使用绝对路径和 toolchain 文件：

```powershell
$vcpkgRoot = 'D:\software\develop\CompileLibrary\vcpkg'
$vcpkgToolchain = "$vcpkgRoot\scripts\buildsystems\vcpkg.cmake"

& "$vcpkgRoot\vcpkg.exe" list

cmake -S . -B build-vcpkg -G 'NMake Makefiles' `
  -DCMAKE_TOOLCHAIN_FILE="$vcpkgToolchain" `
  -DVCPKG_TARGET_TRIPLET=x64-windows
```

不要因为 `vcpkg` 不在 `PATH` 就重新下载或重新安装 vcpkg。先使用上面的固定路径。

## CMake 生成器

仓库脚本优先使用 Ninja。当前会话已核验 Visual Studio CMake 扩展中的
`ninja.exe` 可用：

```text
C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja\ninja.exe
```

因此当前 Windows 机器上的可靠选择是：

```text
Ninja + clang-cl；需要 MSVC 兼容生成时可使用 NMake Makefiles
```

直接运行 `scripts\build.bat` 时，脚本会优先选择 Ninja；找不到 Ninja 时自动加载 Visual Studio
开发环境并回退到 `NMake Makefiles`。如果构建目录以前由 Ninja 生成，而当前回退到 NMake，
不要混用同一个构建目录，设置新的目录：

```powershell
$env:BUILD_DIR = 'build-msvc'
scripts\build.bat
```

## C++ 标准

项目和公共 target 统一使用 C++17：

```text
CMAKE_CXX_STANDARD=17
CMAKE_CXX_STANDARD_REQUIRED=ON
CMAKE_CXX_EXTENSIONS=OFF
```

CsString 固定使用 `string-1.4.1`，不要切换到 CsString 2.x；2.x 不属于当前 C++17 构建约定。
